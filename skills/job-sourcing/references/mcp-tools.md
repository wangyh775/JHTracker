# MCP 端口操作与数据安全边界规约 (MCP Tools & Security Reference)

智能体在执行高校/长尾渠道岗位检索、外部信息沉淀、推荐交互和简历分析时，必须严格遵守本交互规约与安全准则。

---

## 1. 核心 FastMCP 工具清单 (Tool Catalog)

| 工具名称 | 作用说明 | 读写权限 | 隔离级别 |
|---|---|---|---|
| `job_add_external` | **智能体专用**：将从高校就业网、宣讲会、科研院所公告等挖掘的岗位安全入库 | 写 (公共库 `public_jobs.db`) | 自动计算确定性 MD5 哈希幂等去重，同步更新 SQLite FTS5 全文索引 |
| `job_search` | 根据关键词、地点、批次、发布时间检索本地库（用于录入前查重或意向查询） | 读 (公共库 `public_jobs.db`) | 只读公共库，安全参数过滤 |
| `job_get_detail` | 获取单个岗位的详细 JD 与原投递链接 | 读 (公共库 `public_jobs.db`) | 只读公共库 |
| `job_recommend` | 基于当前简历与 HITL 特征权重计算契合度推荐列表 | 读/计算 (双库混合) | 仅在本地内存计算，绝不上传云端 |
| `job_agent_push` | **智能体主动特推**：将高匹配度长尾/优质岗位卡片及专属分析理由直推至前端卡片区 | 写 (私有库 `user_data.db`) | 仅写入主动特推表，由用户在前端亲自裁决 |
| `resume_optimize` | 对指定简历针对目标长尾岗位进行 ATS 匹配度分析与针对性优化 | 读/写 (独立版本) | 原始简历只读不可覆写，优化结果独立存储为 AI 版本 |

> **架构与权限分工说明**：
> 1. **全网爬虫自动化**：各大主流门户（求职方舟、牛客、超级简历等）由后端调度定时批量同步，**智能体 Skill 不再负责调用批量爬虫**，专心作为“长尾网络情报员”。
> 2. **智能体核心写操作**：仅允许通过 `job_add_external` 将网络检索到的高质量高校/专场招聘沉淀入公共库。
> 3. **投递看板写权限隔离**：投递看板的阶段推进与变更（`application_update_status`、`tracker_add_custom_job` 等）属于用户私人流程控制，**不对智能体开放写权限**，仅限用户在 UI 上操作。

## 2. 数据安全与隐私隔离红线 (Security Boundaries)

1. **双库硬隔离**：
   - 公共岗位数据持久化在 `data/public_jobs.db`，所有求职者共享。
   - 个人隐私数据持久化在 `~/.JHTracker/user_data.db`，严禁任何外部网络上报行为。
2. **原始简历保护与版本隔离**：
   - 用户的原始简历（`version_type: ORIGINAL`）仅限用户手工编辑，智能体完全只读。
   - 智能体/系统优化产出的简历必须标记为 `AI_OPTIMIZED` 并关联 `parent_resume_id`，独立保存，严禁任何覆写行为。
3. **看板写权限隔离**：
   - 智能体无权添加或流转用户的投递状态，投递看板完全由用户自主掌控。
4. **禁止执行原生指令与注入**：
   - 智能体严禁向后台传递包含 SQL 注释（`--`, `/*`）、`DROP/DELETE/UPDATE/UNION` 等高危注入片段。
   - 严禁向后台要求获取本地数据库物理路径或原生 SQLite Connection 句柄。
5. **输入参数标准化白名单**：
   - ID 必须符合 `^[a-zA-Z0-9_-]{1,64}$`；
   - 链接必须是合法的 `http://` 或 `https://` 协议，禁止 `javascript:` 或本地文件协议。
