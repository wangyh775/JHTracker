# 高校与长尾渠道校招网络挖掘技能 (Campus & Long-tail Job Sourcing Skill)

本 Skill 指导智能体（Agent）作为“全网情报侦察兵”，利用联网检索能力对**各大高校就业信息网、高校宣讲会、专场引才公告、科研院所及央国企专区**等非标准化渠道进行深度搜寻，提炼高价值且爬虫难以触达的校招岗位，并通过 **JHTracker** FastMCP 端口沉淀到系统公共库并进行契合度推荐。

---

## 触发场景 (When to Use)

当用户提出如下需求时，主动使用本技能：
- “帮我查一下各大高校（如华科、哈工大、大连交大等）就业网最新的秋招/春招宣讲会与招聘公告”
- “网上有哪些近期发布的研究所、国企、央企校招专场信息？”
- “在高校就业网上搜索匹配我简历技术栈（如 C++、SLAM、嵌入式、算法等）的独家校招”
- “从这篇学校就业网的招聘通告/宣讲会文案中提取细分岗位并录入系统”
- “针对挖掘到的目标岗位，分析与我简历的契合度并生成定向优化建议”

*(注：各大标准化招聘平台如求职方舟、牛客、超级简历等已由后台自动化爬虫定时同步，本 Skill 专攻入口分散、非标准化的长尾信息网络检索)*

---

## 核心工作流 (Agent Workflow)

### 步骤 1: 制定精准网络检索策略 (Targeted Web Search)
根据用户意向城市、高校层级、专业技术栈或企业类型，使用专业搜索算子（如 `site:edu.cn`）进行网络检索。详见 `references/campus-search-patterns.md`。

**常用检索范式示例**：
- **目标高校就业网直搜**：
  `site:*.edu.cn "2027届" OR "2026届" "秋季校园招聘" OR "空中宣讲会" "C++" OR "算法"`
- **重点央国企/科研院所专场**：
  `"研究所" OR "央企" "2027届校园招聘" ("就业网" OR "网申地址" OR "投递邮箱") -site:zhaopin.com -site:51job.com`
- **特定高校就业系统检索**：
  `site:career.*.edu.cn OR site:job.*.edu.cn "招聘简章" "计算机" OR "软件"`

---

### 步骤 2: 结构化解析与信息提取 (Information Extraction)
高校就业网通告通常是非结构化长文。智能体必须阅读并提炼出以下核心要素：
1. **企业全称 (`company`)**：例如“中国铁路通信信号股份有限公司”。
2. **细分岗位 (`title`)**：通告若包含多个方向（如“招聘软件开发、信号控制、算法工程师”），**必须按具体工种拆分成多条独立岗位记录**，严禁堆砌合并。
3. **真实投递途径 (`detail_url` / `description`)**：
   - 优先提取企业自建校招系统链接（如 Moka、北森、飞书招聘、企业官网 ATS）；
   - 若为高校专属网申或邮箱投递，将投递邮箱与邮件主题规范（如 `校招-岗位-姓名`）写入 `description`。
4. **招聘批次与毕业年份 (`batch` / `target_grad_year`)**：如“2027届秋招”、“2026届应届生”。
5. **工作地点与学历门槛 (`location` / `education_req`)**。
6. **信息源高校/平台 (`source_site`)**：标注具体出处，如 `哈工大就业网`、`清华大学学生职业发展指导中心`、`国聘网`。

---

### 步骤 3: 查重并录入公共岗位库 (Deduplication & Ingestion)
在沉淀岗位前，可先调用 `job_search` 确认库内是否已收录：
```json
{
  "tool": "job_search",
  "arguments": {
    "keyword": "企业全称 岗位名",
    "limit": 5
  }
}
```
确认无重复后，调用 `job_add_external` 将提炼的岗位写入公共库 `data/public_jobs.db`。后台会自动基于 `(company, title, detail_url)` 计算确定性 MD5 哈希去重并更新 FTS5 全文索引：
```json
{
  "tool": "job_add_external",
  "arguments": {
    "company": "中国通号研究设计院",
    "title": "列控算法工程师（2027届秋招）",
    "location": "北京",
    "industry": "轨道交通/通信",
    "detail_url": "https://crsc.zhiye.com/campus/detail?jobId=12345",
    "batch": "2027届秋招",
    "target_grad_year": 2027,
    "education_req": "硕士及以上",
    "description": "【岗位职责】负责列控核心安全算法设计与仿真...【投递通道】官网直申，宣讲现场接收简历",
    "source_site": "大连交大就业网"
  }
}
```

---

### 步骤 4: 结合当前简历匹配评估与专属推送 (Deep Profile Matching & Push)
长尾渠道挖掘入库的岗位，若与当前用户简历高度契合，可直推用户前端专属卡片区：
- **查阅简历画像**：调用 `resume_get_profile()`，明确用户专业方向（如机械工程、FDM 3D打印、热端流体与温控）与核心技能；
- **精准度研判**：严禁仅命中通用工具（如 Python）就将非技术类岗位推送给工科生；
- **合规推送**：推荐理由需清晰阐明契合的具体课题/方向（不少于 12 字），并严格遵守企业去重与频控规则（已投企业不推，待投满 3 岗企业不推），通过 `job_agent_push` 推送到卡片区。

---

### 步骤 5: 简历定向微调与版本隔离优化 (Resume Customization)
若用户希望对挖掘到的长尾优质岗位进行专岗针对性投递，调用 `resume_optimize`：
```json
{
  "tool": "resume_optimize",
  "arguments": {
    "resume_id": "res_active",
    "job_id": "job_xxxxxx",
    "optimization_type": "TARGETED",
    "save_as_version": true
  }
}
```

## 行为红线与规范 (Safety & Boundaries)

1. **原始简历绝对只读**：严禁覆写用户自己编写的原始简历，所有优化必须保存为独立的 `AI_OPTIMIZED` 子版本。
2. **看板流程属于用户**：投递状态推进（投递、笔试、面试等）由用户在前端看板手动流转，智能体不具备看板写权限。
3. **真实性优先**：高校就业网信息可能有时效性或宣讲场地变动，提取信息时务必核实发布日期与有效截止期，严禁虚构网申链接或投递邮箱。
4. **一岗一录入**：高校大通告必须切分为细分子岗位，禁止将“电气、机械、土木、计算机”合并为一条录入，以便精准匹配。
5. **合规推送与真实对口**：对于外部挖掘的高契合度岗位，在推送前应确保契合用户简历方向，推荐理由应具体真实，避免空泛。
6. **企业频控红线**：严禁对已投递状态的企业进行重复推荐/推送；单企业在待投递列表中最多允许 3 个岗位，达到或超出上限的企业严禁再次推送。
